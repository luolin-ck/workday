# 迭代日志

每次迭代新建 `YYYY-MM-DD-HHMM-short-topic.md`，同一轮后续进展更新原记录。日期与时间使用实际记录时间；不能倒填。开发规范统一见 [AGENTS.md](../../AGENTS.md)。

记录应包含：

- 需求、范围及最终修改。
- Red / Green / Refactor 的实际顺序；命令、执行时间、退出码、关键结果与证据路径。未保存失败证据或先实现后补测须明确标注。
- 环境/夹具错误单独记录，不能当作业务 Red。
- 验证和交付状态，包括 stage、实际应用是否更新与已验证范围。
- 未验证项、已知限制及后续步骤。文档或样式改动说明对应检查，以及没有行为单测的原因。

测试输出放在 `test-results/`，界面截图与烟测结果放在 `output/playwright/`，日志使用相对链接引用。不要复制全部输出；保留足以复核的结论和原始证据。日志不记录密钥、用户个人数据或敏感模型消息。

可用下面的精简模板，不适用的步骤说明原因即可：

```md
# 主题
记录时间：YYYY-MM-DD HH:mm（时区）

## 需求与范围
...

## 测试顺序和证据
Red：命令、时间、退出码、预期失败、证据路径（或说明非测试先行）。
Green：命令、时间、退出码、通过范围、证据路径。
Refactor：必要整理和回归，或未整理原因。

## 结果与交付
...

## 未验证项与风险
...
```
